## 1. 主要诊断结论

开发集的高表现主要来自 **image 类样本过少造成的不稳定乐观估计**，而不是正式集的干预证据明显更弱或 API 有效率明显变差。

- 开发集只有 7 个 image 真值，答对 5 个，image 召回 71.43%；
- 正式集有 42 个 image 真值，只答对 11 个，image 召回 26.19%；
- 两组预测 image 的比例相近（25.00% vs 22.71%），说明模型并非在正式集简单停止预测 image；它是在大量 text 样本上错误声称依赖 image；
- 开发集到正式集的宏召回差值为 −23.70 个百分点，用户级独立 bootstrap 95% CI 为 −42.11 至 −1.90 个百分点；这是事后诊断区间，不是新注册的确认性检验。

## 2. 开发集与正式集并没有明显“难度漂移”

| 项目 | 开发集 | 正式集 |
|---|---:|---:|
| 样本 / 唯一用户 | 80 / 79 | 590 / 583 |
| user bucket | 0 | 1–9 |
| text / image | 73 / 7 | 548 / 42 |
| 有效率 | 93.75% | 92.71% |
| 绝对 contrast 中位数 | 0.733 | 0.736 |
| contrast MAD 中位数 | 0.121 | 0.124 |
| 预测 image 比例 | 25.00% | 22.71% |
| ITT accuracy | 72.50% | 67.29% |
| ITT macro recall | 72.02% | 48.31% |

绝对干预强度、干预波动、有效率和预测类别比例都很接近。开发集来自 bucket 0，正式集来自 bucket 1–9，这是设计上的域切分；但现有描述性数据不支持把下降简单归因于正式集“证据更弱”。

## 3. image 失败不局限于弱证据

在 42 个 image 真值内部按绝对 contrast 四分位完整分层：

| 强度层 | n | contrast 范围 | 有效率 | image 召回 |
|---|---:|---:|---:|---:|
| Q1 | 11 | 0.266–0.556 | 100.00% | 27.27% |
| Q2 | 10 | 0.561–0.602 | 70.00% | 20.00% |
| Q3 | 10 | 0.606–0.697 | 90.00% | 30.00% |
| Q4 | 11 | 0.710–0.833 | 100.00% | 27.27% |

最高强度 Q4 仍只答对 3/11，与最低强度 Q1 相同。因每层只有 10–11 条，不能断言四层完全等价；但至少没有看到“只要 image 干预足够强，LLM 就能识别”的趋势。

text 类四分位召回分别为 74.29%、73.13%、65.69%、68.61%。最强干预层没有带来更高解释一致性，因此解释中的自信判断与行为干预强度并非简单同步。

## 5. 失败机制与置信度

- 112 条首次非有效并发生重试，69 条恢复；最终 40 条 schema 无效、3 条 API 失败；
- 永久失败的真值构成为 text 39、image 4，与总体类别不平衡大致一致；
- 开发集与正式集有效率只差 1.04 个百分点，所以格式/API 失败不是宏召回下降的主要解释；
- 547 个有效回答中，置信度 0.8–0.9 有 383 条、0.9–1.0 有 112 条；对应准确率只有 72.85% 和 74.11%；
- 有 133 个置信度 ≥0.8 的错误回答。自报置信度集中在高位，区分正确与错误的能力有限。

## 6. 我们现在知道什么

**证据支持：** v2 在开发集的 image 召回由 5/7 个样本支撑，估计非常脆弱；在更大的未见确认集中，模型常把 text 驱动误解释成 image 驱动，并且这种问题没有随干预强度增加而明显消失。

**证据不支持：** 不能声称某个 user bucket 特别适合或不适合 Kimi；每桶 image 数量太少。不能把事后 bootstrap 区间当作预注册的显著性证明。不能据此修改 Day 15 的主结果。

**研究含义：** 这不是“实验做失败了”，而是得到一个清楚的负结果：自然语言解释对模型行为证据的模态归因可能高置信但不忠实，且小型提示词开发集会严重高估这种能力。

## 7. 下一道门

若继续实验，下一阶段应是独立的探索性机制研究，而不是对 590 条正式集调参：

1. 从既有结果中建立不接触新测试集的训练/开发方案；
2. 比较自然解释、结构化证据对齐提示和无需 LLM 的简单基线；
3. 预留全新的未见用户分桶或新数据集进行最终验证；
4. 在任何新模型选择前做 image 类样本量与宏召回区间的功效规划。

完整机器可读结果见 `data/manifests/kimi_v2_posthoc_error_audit.json`。
