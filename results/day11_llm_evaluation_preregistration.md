## 1. 这一步到底在做什么

前十天回答的是：“MGCN 在做推荐时，图片和文字哪一个更能改变推荐结果？”

这一步要回答的是：“LLM 给出的自然语言解释，声称依赖的图片/文字，是否与 MGCN 实际更敏感的模态一致？”

这里的“正确答案”不是人工印象，而是已经完成的模型干预结果：分别破坏图片特征和文字特征，看目标商品的排名变化。三个独立训练种子、两种确定性干预和五个置换种子一致时，才得到最严格的 A 级标签。

本实验**只检验图片与文字的归因一致性**。现有干预没有给“历史行为”或“协同信号”制作可靠标签，因此论文不能把这两项也写成已验证的忠实性。

## 3. 连续强度，而不只是二分类

每个用户—商品对共有 21 次测量：

- 3 个训练种子；
- 每个种子包含 zero、mean 和 5 个 permutation 干预；
- 每次分别测图片和文字被干预后的绝对排名变化。

连续对比度定义为：

`(文字排名变化 - 图片排名变化) / (文字排名变化 + 图片排名变化)`

取 21 次测量的中位数作为主要连续强度。接近 `+1` 表示更依赖文字，接近 `-1` 表示更依赖图片，接近 `0` 表示两者难分。分母为零时记为平局，不强行赋予方向。

`6802B7D6E465392830351D6A04A4BD38A83472AE6EECF0755B9833D6D3377821`

## 4. LLM 能看到什么

盲测输入只包含可供人理解的信息：

- 目标商品标题；
- 目标商品描述；
- 目标商品图片；
- 该用户最多 5 条训练集历史商品，按时间戳从新到旧选择；时间戳并列时按内部
  item ID 从小到大打破平局；
- 每条历史同时提供标题和图片，避免只给历史文字而人为偏向文字模态；
- 明确标记哪些字段缺失。

LLM **不能看到**干预标签、连续敏感度、训练种子、排名变化或队列名称。否则相当于把答案写进题目。

主实验采用“无标签解释”提示词。另设“证据感知/允许拒答”提示词作为缓解方法，但它不能冒充独立忠实性测量；如果直接告诉模型真实模态，其一致率没有证明意义。

## 5. 冻结的结构化输出

模型在自然语言解释之外必须返回可解析 JSON：

```json
{
  "explanation": "简短解释",
  "primary_evidence": "image|text|both|history|collaborative|insufficient",
  "claimed_image_share": 0.0,
  "claimed_text_share": 0.0,
  "confidence": 0.0,
  "conflict_detected": false,
  "abstained": false
}
```

规则：

- share 和 confidence 必须在 `[0, 1]`；
- 图片与文字 share 之和必须为 1；若 `insufficient`，二者均为 0；
- `abstained=true` 时，`primary_evidence` 必须是 `insufficient`；
- 声称使用 history/collaborative 会被记录，但不把它们判成“真”或“假”；
- JSON 外的文字不参与自动打分。

## 6. 主要指标

唯一的确认性主指标是严格确认集上的**图片/文字宏平均召回率**：

1. `primary_evidence=text` 预测为文字；
2. `primary_evidence=image` 预测为图片；
3. `both/history/collaborative/insufficient` 在主指标中均视为未正确识别目标模态；
4. 分别计算文本召回率和图片召回率，再取平均。

选择宏平均而不是只看总准确率，是因为确认集有 548 个文本样本、只有 42 个图像样本。一个永远回答“文字”的模型，总准确率会看起来很高，但宏平均召回率只有 0.5。

同时报告：

- 总准确率与混淆矩阵；
- 文本、图像各自的召回率；
- 按用户聚类的 10,000 次 bootstrap 95% 置信区间；
- LLM 的 `claimed_text_share` 与连续对比度的 Spearman 相关及聚类 bootstrap 区间。

图像严格样本只有 42 条，因此图像方向只能给出带宽较大的区间，不作“普遍适用于所有图像商品”的强结论。

## 7. 次要分析

### A+B 敏感性集

在 200 个文本与 200 个图像样本上重复主要指标。它用于判断结论对较宽松标签是否敏感，不替代严格主结果。

### 不稳定集

这里没有图片/文字真值，因此不算准确率。主要观察过度自信率：

`confidence >= 0.8`、没有拒答，并且明确选择 `image`、`text` 或 `both` 的比例。

同时报告拒答率和平均置信度。理想系统应在干预证据不稳定时降低置信度或拒答。

### 多重比较

只预先指定一个模型与一个基础提示词作为主分析。其他模型、提示词或消融全部标为探索性；若同时做显著性检验，使用 Holm 校正，不选择性汇报最好结果。

## 8. API 与失败规则

- 固定模型的精确版本/快照，不能只写会漂移的别名；
- temperature 设为 0；若 API 支持 seed，则固定 seed；
- 每次保存样本 ID、提示词 SHA-256、请求参数、原始响应、解析结果、模型版本、token、费用和时间戳；
- 延迟只用于预算记录，不推断模型能力；
- 网络或服务端错误允许以完全相同请求重试一次；
- 格式错误也只允许一次“原请求重放”，不能针对测试答案修改提示词；
- 第二次仍失败则在意向分析中计为错误/未答，不能静默删除或换样本；
- 开发集完成后冻结提示词哈希，正式集一次性运行，不边看结果边修改。

## 10. 通过与否如何解释

- 主指标明显高于 0.5：LLM 对两种模态的声明有一定区分能力；
- 总准确率高但宏平均接近 0.5：模型可能只是在猜多数类“文字”；
- 二分类一致但连续相关弱：能猜方向，但不能反映依赖强弱；
- 不稳定集仍高置信：解释缺少校准，容易把不可靠证据说得很确定；
- 任何结果都只适用于本数据、MGCN、本输入构造和所用模型版本。

这份预注册的作用，是在看到 LLM 答案之前写清“题目、答案、评分方式和失败怎么处理”，防止结果出来后再改规则。
