# Day 3：BM3 存档恢复与推理路径审计

## 给初学者的结论

今天确认了两件事：

1. 昨天保存的 BM3 模型可以正确读取，读取后给出的推荐结果与训练结束时完全一致；
2. BM3 在“正式推荐”时不会直接读取图片和文字，图片和文字主要在训练时帮助它学习。

第二点改变了下一步实验设计：不能简单地在训练完成后把图片或文字清零，再把“不变”解释成
“模型不依赖图片或文字”。对于 BM3，这种干预放错了位置。

## 1. Checkpoint 恢复验收

输入 checkpoint：

- 模型：BM3
- 数据：Baby
- 最佳 epoch：112
- SHA-256：`D38601C7343D1C77A90E0F7D3F62EEFA9E0F44DCE542A70BFFAD1043AD96119B`

验收过程：

1. 重新建立完全相同的 Baby 数据切分；
2. 创建一个新的 BM3；
3. 把 checkpoint 参数严格加载进去；
4. 重新计算完整验证集和测试集；
5. 把 32 个指标逐项与 checkpoint 记录比较。

结果：

- 缺失参数：0；
- 多余参数：0；
- 32/32 个验证/测试指标完全一致；
- 最大指标差值：0；
- 测试集 Recall@20：0.0862；
- 测试集 NDCG@20：0.0369。

另外固定前 32 位用户的 Top-20 推荐列表，得到推荐指纹：

`0D26F12C4323F6BDDF81E4C5E56FB2C45591A9D93F5C6D103096D52C3BC2E63D`

恢复脚本连续运行两次，完整 JSON 报告的 SHA-256 均为：

`1B0B291EE077E6DA72269D41B67AB9FC941E8C7E7B095453DDB45E76745DCDD2`

因此 checkpoint 恢复路径判定为通过。

## 2. BM3 推理路径实验

实验对象为前 32 位用户、每位用户的全部 7,050 个商品分数，共 225,600 个分数。

依次进行：

1. 不修改模型，再计算一次，作为空白对照；
2. 把全部图像特征及图像投影层清零；
3. 恢复图像后，把全部文本特征及文本投影层清零；
4. 把商品 ID 向量清零，作为应当改变结果的正对照。

| 条件 | 最大分数差 | 是否超过 `1e-6` |
|---|---:|---|
| 什么都不改，重复计算 | 2.38e-7 | 否 |
| 图像路径清零 | 2.38e-7 | 否 |
| 文本路径清零 | 1.79e-7 | 否 |
| 商品 ID 向量清零（正对照） | 1.1045 | 是 |

`1e-7` 量级变化与空白重复计算相同，属于 GPU 稀疏计算的末位浮点抖动；商品向量清零产生
约 1.10 的明显变化，证明探针能够检测真正进入推理路径的参数。

## 3. 为什么会这样

BM3 的图片和文字参与训练损失，帮助用户向量、商品向量和预测层学习。但在
`full_sort_predict()` 中，最终分数只由以下部分计算：

- 用户向量；
- 商品 ID 向量；
- 用户—商品交互图；
- predictor。

图像和文本张量没有被 `full_sort_predict()` 直接调用。

这不表示图片、文字对“训练出来的模型”没有影响，只表示训练结束后再清零图片、文字不能测出
这种历史影响。

## 4. 对后续方案的修正

BM3 的有效模态实验应放在训练阶段，例如：

- Full：正常图片 + 正常文字；
- No-image：训练时移除图像监督；
- No-text：训练时移除文本监督；
- Shuffled-image：训练时打乱图片与商品的对应关系；
- Shuffled-text：训练时打乱文字与商品的对应关系。

比较这些模型的整体指标和同一批用户—商品分数，测量“训练时使用该模态带来了多少变化”。

不过，这种方法更适合测量模型级、用户级或数据切片级影响；如果论文需要对每一次推荐都给出
图片/文字依赖比例，还需要增加一个在推理打分时直接融合模态的模型作为主要审计对象。

## 5. 当前判断

- checkpoint 恢复：通过；
- 推荐基线指纹：已固定；
- 训练后直接图片/文字遮挡：判定为无效设计；
- BM3 训练阶段模态消融：可继续；
- 单条推荐的模态归因：需要重新评估主模型选择。
